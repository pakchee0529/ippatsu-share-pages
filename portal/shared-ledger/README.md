# 正式な新版台帳・保存済み表示の共通入口

共有カード/指示書/入力/日次は `scripts/generate_portal.py` → `apply_saved_ledger_views.transform(root,date,html)` の同じ実装を使用する。日付固定や手動後処理は不要。GUIが起動する外部generatorとdotの非GUI generatorは同じファイル。公開対象日は通常share-update引数で限定する。

入力UIは開発済み入力構造を再利用し、実案件は既存 `photo-ledger-v2` APIで取得する。試験fixture/画像/試験localStorageを参照しない。保存は既存 `ippatsu-photo-ledger/v2` JSON envelope、案件UUID、expected_revision、POST後GET読戻しを使用。追加UIデータは同じJSONの `ledger_ui_v3` に保存し、元の未認識フィールド・写真日・番号・寸法・明示した車種を保持する。DBスキーマ/認証/権限の追加は不要。

未保存下書きは実案件UUID専用の端末キーへ保全するが、共有/指示書/日次はGETした保存版だけを読む。版違い・基準値違い・取得失敗は基準数量と警告を保ち、0へ補完しない。保存前にも現在受付/基準/期待revisionを照合する。合成値を本番保存して確認しない。

数量は付託基準とは別の台帳計画/変更追加として保持する。共有の表配置を変えず `7→5＋2` などで表示し、施工状態・案件数量・予定・履歴は変更しない。柴寸法は整数m、離隔は現場単一の小数1桁。写真枚数は撮影日+番号のE参照を重複排除した数で、本数や撮影完了とは別。

## 会社採用GUIとの境界

採用GUIは公開repoの同じgeneratorを外部runnerで呼ぶ。生成本体の結果一致を確認済み。ただし現採用EXEの後段には旧3リンク必須の `portal_output_guard` とindex/TOPだけの公開許可リストが残る。新導線をGUIから公開するには、この2か所の限定修正を採用実行版へ届ける必要がある。検査を無効化したり旧リンクを偽装して迂回しない。EXEは今回差し替えない。dotの許可済み26日公開は同じ生成出力を確認して限定反映する。

旧版API/保存データ/過去公開ページは削除しない。旧26日adapterは過去の互換用で、通常生成では使用しない。復旧は今回の共通表示ソースと26日生成物だけを前版へ戻す。既に保存された台帳JSONは削除しない。
