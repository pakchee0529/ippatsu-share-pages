# 26日限定：保存済み新版台帳の表示

- 共有カードの表は付託基準のまま生成する。GETした新版台帳の案件ID・作業日・保存revision・original_plannedが一致した場合だけ、既存セルへ `7→5＋2` を重ねる。
- 指示書は単一径間、日次離隔表は全5径間。閲覧処理はGETのみで、localStorageや未保存入力を参照しない。写真枚数は撮影日＋写真番号の参照数で、画像や撮影完了の確認ではない。
- 唯一の入力元は通常の `portal/ledger-v2`。26日だけ補助を読み込み、既存の保存API・expected_revision・読戻しを使用する。付託基準は変更しない。任意の `share_quantity_adjustments` は台帳JSON内の表示用追加数量で、cases/case_details/業務数量は更新しない。写真からの従来の追加判定を維持し、明示入力だけを優先する。途中の写真入力は保存でき、推定できない表示は警告して基準値を維持する。
- 履歴文字列の純粋関数は検証済み試験版の契約を再利用。デモ保存領域やデータは読み込まない。

通常の正式HTML生成後は、公開前に `python scripts/apply_261026_saved_ledger_views.py` を実行する。これは26日の入口と表示スクリプトを再接続する後処理で、中央generatorや他の日付を変更しない。2回実行しても同一出力。基準75値が変わった場合は停止するため、先にconfigと付託根拠を照合すること。

公開の復旧はこの表示変更のファイルだけを変更前へ戻して再配信する。台帳JSON・旧API・旧保存データは削除しない。新しいJSON項目は既存版が保持し、基準数量や施工履歴の復旧操作は不要。保存済み台帳を巻き戻す場合は別の業務判断と既存revision手順が必要。
