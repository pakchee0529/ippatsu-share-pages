# 原典数量の空欄と未参照を区別する恒久規則

本人の訂正指示により、CS・付託の当該数量欄を実参照し空欄と確認できた場合は0として表示する。未参照、判読不能、根拠の矛盾を空欄と推定しない。処理方法、道幅、B車、傾斜、設計番号などの非数量欄にはこの規則を適用しない。

## 共通の判断と経路

- 私有の原典確認入力は `observed_blank / observed_value / not_referenced / unreadable / conflict` を区別する。確認済みの場合は CS/付託の種別、原典hash、ページ、案件・数量欄の一致が必要。OCRの空文字やnullだけでは空欄確認にしない。
- 母艦の `app/share/source_quantity_evidence.py` が純粋な表示投影を担う。JSON CLIとGUIの共通 `payload_from_json_obj` → 通常HTML rendererから使用する。DBの保存・正式確認・receiptを作る機能ではない。
- 週間の既存公開原典に対する訂正は `generate_weekly_source_format.py --quantity-evidence <私有確認入力>` で限定する。数値と矛盾する空欄訂正、別日・別案件・非数量・重複は拒否する。
- 認めた空欄0の投影は `scripts/source_quantity_projections.json` に案件/欄/0/確認入力のdigestだけを保つ。原票、原文、私有パスや担当者情報は含めない。通常再生成もこの採用済み投影を読み、私有確認入力を外しただけで未確認へ戻さない。
- 原典確認入力の内容は実際の原典参照で確定する。型検査・hash・合成テストは本人確認や原典を見た証明ではない。

## 3画面と表示

共通入口は `apply_saved_ledger_views.transform`。通常の共有ページreadability処理、概要、関連導線、カードfooter、日次/指示書テンプレートを同じ経路で作る。sourceOnly は原典数量の投影を通常の `views.mjs` / `renderProjection` に渡す限定条件であり、別の簡易帳票を正本にしない。

共有の通常 `data-daily-clearance` 入口と各カードfooterから日次離隔表へ進み、各カードから当該指示書へ進む。TOPは各日1つの通常共有入口を維持する。原典の注釈・正式保存未確認の長文・候補説明などを指定外の画面説明として追加しない。数値は通常の数値/単位、未参照等は短い未確認表示とし、根拠区分は内部の投影データに保つ。

sourceOnly は `loadDay`、訂正editor、入力/保存/完了handler、自動更新を実行しない。通常の別日と台帳保存の動作は既存のままにする。sourceOnly入力を一般の正式保存済みHTMLとして採用しない。正式保存版への移行は既存receipt/採用手順による別工程である。

## 検査と採用境界

8つの母艦契約試験、6つの私有確認→保持投影→再生成試験、5日分の意味/集合/数量/地図/未知状態試験、通常経路との比較、PC/スマホのTOP→共有→離隔表→各指示書の実操作、不要説明の非表示と無通信、印刷を確認する。manifestは15HTML・対応資産と保持投影を一体で束縛し、通常生成で旧出力を受け入れるためにguardを緩めない。

現時点の保持投影が空である場合、実原典未取得の項目を0へ変更したという意味ではない。会社GUI/EXEの採用、実原典の参照、公開配信、実保存、実地図操作は別状態で報告する。
