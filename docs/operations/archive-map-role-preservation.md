# Archive map role preservation candidate

This candidate is not a complete legacy business-regeneration migration.

An overall-map representative can be a historical midpoint rather than a span endpoint. When an identity-bound baseline already supplies that representative, preserve it and compare explicit plain coordinates with the same role. Keep source/GPS and baseline/source endpoint conflicts, source/prior URL conflicts, and the no-baseline plain/endpoint check.

An existing page cannot distinguish accidentally lost map evidence from deliberately unavailable coordinates. Normal regeneration therefore refuses a newly available published role unless that role exists in a validated baseline. GPS, explicit source fields, plain coordinates, URL-derived representatives, and generated single-map links are all covered. Evidence-bound map restoration remains a separate operation.

The published endpoint projection follows the existing renderer: start and end are visible only when both exist and are distinct. A single internal endpoint may be recomputed when the resulting HTML remains identical. Supplying a second endpoint that enables a new two-point map stops.

## Current limits

The map-only probe preserves all published roles on 20 of the 22 conventional repaired dates. It safely stops on 2026-06-30 and 2026-07-22 because their unverified roles would otherwise be populated. The three immutable ledger aliases use the separate map route. A full generation that includes either stopped date will stop; this candidate is not approved for unrestricted routine deployment.

A follow-up availability contract must bind deliberately unavailable roles to date, exact identity and label, public provenance, and the expected map projection. It must preserve unknown roles without accepting new coordinates, reject contradictory explicit input, and keep the general role-addition guard. Missing historical business exports must not be fabricated for an end-to-end claim.
