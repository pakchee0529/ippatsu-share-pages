# 運搬表示の共通描画修正候補

## 目的と参照正本

11/10の通常日次離隔表・指示書から欠落した運搬欄を復元する。本人が挙げた11/5の運搬あり正本は `portal/archive/261105/saved-forms/final-ledger-8ad48334ad255b519fa7/` の daily.html と instructions.html。西川57E1W4～58E1、受付回1・台帳保存版1の両帳票に「追加・変更・運搬」の行 `運搬 / 運搬 / US×1` がある。

参照SHA256: daily `8bc5f7df916c66b387127039d0463575a6279f5150d4e5d9b5ea88cbd88b75f2`、instructions `183dc3bbf04226c5586b32de85ef6096de166450d92b59447cac04ca1867ac8f`。同ペアは11/7の公開コミット1b52311から現在main d72384bまで保持されている。

11/5の値は登録済みcompletion_note由来であり、写真数から台数を推定したものではない。10/29の写真参照集計型も対照し、両経路を混同しない。今回の通常画面は11/5の見出し・表位置に合わせるが、値の算出は既存の運搬写真参照（撮影日＋番号）の重複除外集計を保持する。車両台数・新たな業務実績を作らない。

## 原因と変更

`ledger-view-model.mjs` の baseGroups が quantityOperations を持つ新形式で早期returnし、旧形式末尾の運搬行生成を通らなかった。運搬集計を共通groupsへ移し、新旧両形式で一度だけ表示する。明示OFF、写真番号の0埋め同一性、撮影日違い、柴寸法の後段位置を保持。実コード変更はこの表示境界だけ。

共通資産・SW・通常生成transformの世代を `20261110-transport-r1` へ揃える。他のコード差分は版文字列のみ。台帳入力・保存・数量計算・認証・API実装・固定アーカイブを変更しない。

## 検査

- 運搬回帰25ケース、新旧形式、選択OFF/欠損、重複、日付違い、0件、両画面の同じ表、写真参照保持、原本不変、11/5両帳票の実markupに合格。
- 取得済み11/10原本の非通信再生で、当時の保存2件はUS×3/US×1。数量投影、非運搬活動行、原本全文は不変。後続入力を上書きしない。
- 柴寸法: 24例、45,268組、異常21、結合11。カード14件。旧ledger-v2 domain/module、SW43件、TOP非表示・空予定・見出し検査に合格。
- compileall、diff-check、資産世代検査に合格。
- 全テスト合格とはしない。既存archive生成検査のstale index、旧継承テストの固定cache版不一致は基点mainでも再現。継承テストの版だけを合わせた非保存試験でも古いfixtureのTR写真配列不足があり、未合格。検査/guardは緩和しない。
- 旧entry再生成検査は別機能の置換だけを許すため、今回のcache版変更を対象外差分とする。今回は通常transformによる二度生成同一性と、3ページの版指定以外不変を別途検査した。

## 経路と現状

公開側通常rendererと日次transformは修正候補。固定archive builder/viewerおよび保存帳票は不変。会社PC GUI/EXE、製品同梱renderer、保管キットは未反映・未検証で、全経路一致を主張しない。

修正前の公開離隔表で運搬欠落を実確認。ローカル候補ブラウザは接続できず未検証。最新原本再照合と修正後の実ブラウザ確認は未完了。候補はローカルのみ、push/PR/merge/Pages公開は未実施。

## 復旧

候補の採用前は本番変更なし。採用する場合は対象差分だけを適用し、同一commitの配信/HTTP/実表示を確認する。問題時は後続変更を照合し、この表示変更と版参照だけを戻す。保存台帳、写真、下書き、旧cacheを削除しない。
