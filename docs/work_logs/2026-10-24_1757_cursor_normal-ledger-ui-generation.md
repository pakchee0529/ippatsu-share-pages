# 正式新台帳UIと共通生成経路

ユーザーのUI切替と生成全経路統合の承認に基づく変更。開発済み入力構造を通常台帳へ接続し、26日を公開対象にする。他日付は隔離生成だけで確認し、過去公開日/OJT/デモは更新しない。

## 変更

- `portal/shared-ledger/`：正式入力UI、既存v2 API/UUID/expected_revision/読戻しadapter、保存済みだけを読む共有/指示書/日次表示。端末下書きは案件UUIDごとに分離し、デモデータを参照しない。
- `scripts/generate_portal.py` と `apply_saved_ledger_views.py`：日付共通の自動接続。GUI外部runner/通常CLI/再生成が同じ実装を使用し、追加の手動後処理は不要。
- `share/261026/` の共有/指示書/日次のみを新しい正式UIへ接続。旧26日資産は互換用に保持。

元75数量、条件（4件B車不可/集積と78～79の条件）、地図、予定、施工状態、元台帳、履歴を保持。DB/権限/認証/DDLは変更しない。新UI情報は既存台帳JSONの追加項目として保存可能であることを現API実装で確認。

## 確認

モデル8項目、スマホ390/PC1100の入力→合成API保存→読戻し→指示書/日次/共有→再読込、競合拒否を検証。生成経路16項目でCLIと採用GUIの実外部runnerの同一HTML、別2日付の隔離生成、数量/条件/地図/リンク/日次と冪等性を確認。本番案件への合成保存は禁止し、実APIはGETのみ。

## 採用GUIに残る境界

生成実装は共通化したが、採用EXEの公開後段は旧3リンクを必須にし、許可パスを当日index/TOPに限定している。単位付き数量の既存parserも限定対応が必要。数量・地図保護を維持した3モジュールの候補パッチは隔離検証済みだが、採用ソース/EXEへは適用していない。GUIで新導線の公開まで完了とは扱わず、検査を迂回しない。EXE差替えは別の適用判断。

## 復旧

今回の生成/共通表示ソースと26日生成物の限定差分を前版へ戻す。保存済み台帳JSONや旧API/履歴を削除しない。既存の訂正132件、予定apply、付託取込は再実行しない。
